## 前言
靶场为州学弟-特洛伊挖矿应急响应
特洛伊木马挖矿病毒与常规挖矿病毒不同，特洛伊会对 linux 文件进行感染，例如 top/ps 等命令返回空可能是 `/tmp/top` 被感染、添加至环境变量劫持、alias 别名。

此靶场挖矿 cpu 占用是低占用，比较难分辨，且外联排查存在 30 秒静默（每 30s 发一次包）。

- 绝对路径：`/tmp/kworkerds`
- 外联 ip：`104.21.6.99:10235`
- 守护进程是 `/usr/bin/.0guardian`
- 定时任务 `/etc/cron.d/0guardian`

应急目标：
- 找出挖矿文件，填写其绝对路径
- 提取挖矿程序外联的 IP 与端口，格式填写 ip:port
- 终止挖矿进程并删除病毒程序，写出守护进程脚本的绝对路径
- 分析病毒源码逻辑，按文件内顺序，依次对指定感染程序求 MD5 值并提交结果
- 系统断网无外网，使用本地 deb 安装包修复被篡改程序，修复完成后读取 `/var/flag/1` 内 flag 值

---

## 1. 上机排查

上机后 top 输出为空，ls、ps 等正常，说明病毒对 linux 的部分内核文件进行了修改，排查以下可能：
1. alias 别名
2. 命令添加至环境变量劫持
3. `/tmp/top` 等文件被感染
4. 内核级隐藏

---

## 2. alias 别名排查

alias 发现输出 `alias top='echo ""'`，说明 top 被别名导致我们输入 top 输出为空，`unalias top` 删除别名，top 恢复正常。

![alias排查结果](/assets/img/trojan/1.png)

---

## 3. 挖矿进程排查

已知告警为木马挖矿，但无木马挖矿第一个特征 cpu 高占用，因此判定为低占用型挖矿病毒，记录其 pid 与文件路径。

![挖矿进程排查](/assets/img/trojan/2.png)

找出挖矿文件，填写其绝对路径：**`/tmp/kworkerds`**

![挖矿文件路径](/assets/img/trojan/3.png)

---

## 4. 外联 IP 排查

使用以下命令查看外联 ip：

```bash
netstat -antp
ss -antp
ss -tupan | grep "kworkerds"
```

![外联IP排查](/assets/img/trojan/4.png)

可以看到，我们使用 `netstat -antp` 时并没有第一时间出现外联 ip 而是多次使用后才出现，说明此挖矿病毒不是常外联，会静默发心跳包进行链接。

提取挖矿程序外联的 IP 与端口：**`104.21.6.99:10235`**

![填写外联IP](/assets/img/trojan/5.png)

---

## 5. 定时任务与守护进程排查

删掉程序与杀死进程发现，进程 pid 更改且程序恢复，说明存在病毒守护脚本，查看定时任务：

```bash
crontab -l
ls -la /etc/cron*
```

![定时任务排查](/assets/img/trojan/6.png)

发现当前用户下无异常定时任务，但在 cron* 的目录下存在较多定时文件，进行定时任务排查：

```bash
cat /etc/cron.d/0guardian
strings /root/usr/bin/.0guardian
```

![守护脚本内容](/assets/img/trojan/7.png)

找到病毒守护脚本的定时任务，将脚本放到 ai 进行分析：

```bash
#!/bin/bash
# 脚本解释器声明：指定使用bash shell执行此脚本

# Guardian Script: Periodically triggers an infected command
# 守护脚本：定期执行一个指定命令
# to ensure the core service is checked and revived if needed.
# 用于确保核心服务被检查，并在需要时重启/恢复服务

# 核心命令：执行stat命令检查/tmp目录状态，屏蔽所有输出信息
/usr/bin/stat /tmp > /dev/null 2>&1
```

代码分析发现此脚本正常，无恶意功能，但是却是定时任务文件且位置为隐藏目录，命令运行看一下执行结果：

```bash
stat /tmp
stat /tmp/kworkerds
busybox stat /tmp/kworkerds
```

![stat命令异常](/assets/img/trojan/8.png)

其余都正常，但是当 stat 为病毒文件输出为空，此时说明 stat 被感染，可能存在黑白名单，进行过滤。

终止挖矿进程并删除病毒程序，写出守护进程脚本的绝对路径：**`/root/usr/bin/.0guardian`**

---

## 6. 病毒溯源与清理

当我们删除定时任务、守护脚本发现，仍然无法删除病毒，进行溯源查看病毒来源，通过堡垒机与运维人员的补充发现，病毒传播途径为运维人员下载未知软件导致感染，在沙箱下下载软件进行分析。

![溯源分析1](/assets/img/trojan/9.png)

将可疑文件放入 ida 进行反编译查看源码，发现是其将 linux 的 tmp 目录下感染，所以病毒删除会恢复。

---

## 7. 系统修复

系统断网无外网，使用本地 deb 安装包修复被篡改程序：

```bash
find / -name deb_final
cd deb_final
dpkg -i *.deb
```

![修复完成](/assets/img/trojan/10.png)

再次尝试清理病毒，清理后监测 10 分钟，无复发情况，应急完成。
